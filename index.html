الـ Operating System🔥 مهم
الـ Operating System هو software بيتحكم في الـ hardware (processors, storage, input/output devices, communication devices and data) وبيديره، وبيشتغل كـ resources allocator. وبيتعرّف كمان إنه البرنامج اللي بيتحكم في execution of application programs، والوسيلة اللي بيتم بيها التحكم في allocation and usage of hardware resources وتنسيق كل الـ software activities جوه الكمبيوتر.
📍 p.3 · p.4
مكان الـ OS
الـ OS بيقعد بين الـ hardware وبين الـ System and Application Programs (زي Editors, Games, Compilers, Database)، والـ users بيتعاملوا مع الـ programs دي من فوق.
📍 p.5
Operating System objectives🔥 مهم
للـ OS تمانية أهداف، وكل هدف له معنى محدد.
  • Convenienceبيخلّي الكمبيوتر أسهل في الاستخدام.
  • Ease of Communicationبيسهّل التواصل بين الـ computer والـ user عن طريق friendly user interface، وكمان بين مكونات النظام نفسها.
  • Abstractionبيوفّر programming model مستقل عن الـ hardware (Hardware-independent).
  • Efficiencyبيسمح باستخدام الـ computer system resources بطريقة كفؤة.
  • Monitoring and Alertingبيراقب الـ failures والمشاكل وبينبّه عليها.
  • Ability to Evolveبيسمح بـ development و testing وإدخال functions جديدة من غير ما يتعطّل أو يتأثر شغل الخدمات.
  • Protectionبيضيف layer من الـ security عشان مستوى معيّن من الأمان يفضل موجود وتتحمي data الـ user.
  • Increasing performanceبيرفع الـ throughput لأقصى حد وبيقلّل الوقت اللازم لتنفيذ الأمر.
📍 p.6 · p.7
Operating System services🔥 مهم
الـ OS بيقدّم مجموعة خدمات، كل خدمة ليها وظيفة واضحة.
  • Program developmentبيوفّر أدوات للمبرمج زي الـ editors والـ debuggers.
  • Program executionبيعمل Load للبرنامج والـ data وبيجهّز الـ environment قبل التشغيل.
  • Access to I/O devicesبيحاول يقرأ من الـ ports والـ units ويكتب عليها.
  • Controlled access to dataبيحمي الوصول للـ data (Access protection).
  • System accessبيتأكد من هوية الـ user (User authentication).
  • Error detection and responseلو حصل error لازم تظهر error message. والـ errors نوعين: hardware errors (internal و external زي Memory error و Device failure)، و software errors (زي Arithmetic overflow و الوصول لـ memory locations ممنوعة).
  • Accountingبيجمّع statistics وبيراقب الـ performance، وممكن يتستخدم في توقّع التحسينات المستقبلية أو في billing users.
📍 p.8 · p.9 · p.10
Functions of an OS on a network🔥 مهم
على الـ network الـ OS ليه ست وظايف.
  • Sharing H/Wبيخلّي الـ users يتشاركوا في الـ hardware.
  • Share dataبيسمح للـ users يتشاركوا الـ data.
  • Preventing interferenceبيمنع الـ users من التداخل مع بعض.
  • Scheduling resourcesبيرتّب مين ياخد الـ resources ومتى.
  • Organizing dataبينظّم الـ data عشان الوصول ليها يبقى secure and rapid.
  • Network communicationsبيتعامل مع الاتصالات على الـ network.
📍 p.11
Components of Computer System🔥 مهم
مكونات الـ computer system هي Input devices, Processing devices (CPU), Output devices, Storage devices, Applications software (زي Word Processing, Spreadsheet, Database)، و System software (الـ Operating System والـ Utilities). الـ Users أو end users هما الناس اللي محتاجين الـ output اللي الـ computer systems بتطلّعه، والـ Programmers هما اللي شغلتهم يكتبوا البرامج اللي بتوفّر المعلومات دي.
📍 p.12
Layers of Computer System
الـ computer system طبقات من فوق لتحت: Application Programs, Utilities, Operating Systems, Computer Hardware. الـ End User بيتعامل مع الـ Application Programs، والـ Programmer مع الـ Utilities والـ Operating Systems، والـ Operating System Designer مع الـ Computer Hardware.
Application Programs→Utilities→Operating Systems→Computer Hardware
📍 p.13
Computer-System Operation
الـ I/O devices والـ CPU بيقدروا يشتغلوا concurrently. كل device controller مسؤول عن نوع device معيّن وليه local buffer (memory). الـ CPU بينقل الـ data بين الـ main memory والـ local buffers، والـ I/O بيبقى من الـ device للـ local buffer بتاع الـ controller.
📍 p.14
Storage-Device Hierarchy
الـ storage systems متنظّمة في hierarchy على حسب Speed و Cost و Volatility.
registers→cache→main memory→electronic disk→magnetic disk→optical disk→magnetic tapes
📍 p.15
الـ Kernel
الـ Kernel module مسؤول عن Memory allocation, Garbage collection, Object finalization, Module termination، وعن الـ interfacing مع الـ underlying operating system والـ clock functions. وهو في مركز الدايرة، وحواليه الـ Services وبعدها الـ User Processes.
📍 p.16
Types of Computer Systems
أنواع الـ computer systems تمانية: Simple Batch, Multi-programmed Batched, Time-Sharing, Personal-Computer, Parallel, Distributed, Real-Time، و Handheld.
📍 p.17
Simple Batch System
بيشغّل job واحدة بس في الوقت، وبيعمل smoothed transition بين الـ jobs عشان يوصل لـ maximum utilization. الـ programs والـ data بتتقدّم في groups أو batches.
📍 p.18
Multi-programmed Batch System
بيستخدم job scheduling لزيادة استغلال الـ resources، وبيخزّن أكتر من program في الـ memory. قايم على إن أي job نادرًا بتستخدم كل موارد الكمبيوتر، فلما job تستنى I/O تقدر job تانية تستخدم الـ CPU أو أي I/O.
📍 p.19
Time Sharing System
بيستخدم time sharing للـ switch بين jobs كتير. هو interactive وبيدّي low response time للـ users، وبيتعامل مع أعداد كبيرة من الـ users التفاعليين في نفس الوقت. الـ program بتشارك في الوقت بس لو موجودة في الـ memory.
📍 p.20
Personal System
في الـ Personal System (Desktop) كل user عنده memory و processors و I/O devices خاصة بيه. بقى ممكن بعد الاستثمار في الـ microprocessors، وممكن الـ data تتشارك بين الـ users عن طريق networks.
📍 p.21
Distributed System🔥 مهم
هي computers مستقلة بتتواصل عن طريق network (WAN أو LAN) وبتشتغل كأنها system واحد. الـ computing ممكن يتوزّع على الـ sites بدل مكان مركزي، وبيتميز بـ incremental growth.
  • WANWide area network، شبكة واسعة بتربط الـ computers.
  • LANLocal area network، شبكة محلية بتربط الـ computers.
  • Client-Serverالـ client هو computer محتاج service، والـ server هو S/W أو H/W بيعمل service واحدة زي Printing, graphics, DB, e-mail.
  • Peer-To-Peercomputers decentralized بتقدّم services لبعض (peers).
📍 p.22
Parallel System
الكمبيوتر فيه two or more CPUs بيشاركوا common bus. الـ job لازم تتقسّم لـ jobs صغيرة discrete (independent). والـ exponential speed up في الحساب بيحتاج exponential increase في عدد الـ processors.
📍 p.23
Real-time System🔥 مهم
بيتستخدم غالبًا كـ control device في application مخصص زي Controlling scientific experiments, Medical imaging systems, Industrial control systems. عنده fixed-time constraints واضحة، وبيكون إما hard أو soft.
📍 p.24
Hard و Soft real-time
الـ Hard real-time فيه secondary storage محدود أو مش موجود، والـ data بتتخزن في short term memory، وبيتعارض مع الـ time-sharing، وما بيتدعمش في general purpose OS. الـ Soft real-time مفيد في applications زي multimedia و virtual reality وبيحتاج Advanced OS features.
Hard real-time
  • limited or absent secondary storage
  • short term memory
  • conflicts with time-sharing
  • not in general purpose OS
VS
Soft real-time
  • multimedia
  • virtual reality
  • advanced OS features
📍 p.25
Handheld Systems
بتشمل Personal Digital Assistants (PDAs) والـ Cellular telephones. مشاكلها: Limited memory, Slow processors, Small display screens.
📍 p.26
Computer Categories
الكمبيوترات بتتصنّف لأربع فئات: microcomputers (صغيرة), midrange computers (متوسطة), mainframe computers (كبيرة)، و supercomputers (كبيرة جدًا)، وفئة جديدة ناشئة هي mobile devices. كل ما الكمبيوتر يكبر بتزيد الـ processing power: بيعالج الـ data بسرعة أعلى، وبيعمل معالجة أعقد، وبيستوعب support devices أكبر وأقوى.
📍 p.27 · p.28
Mobile Devices
الـ mobile device جهاز صغير جدًا مبني على wireless phone أو pager. بيدّي limited Internet access زيادة على وظايفه العادية زي المكالمات واستقبال وإرسال الـ pages أو الرسايل.
📍 p.29
Personal Computers🔥 مهم
في أوائل السبعينات حصل breakthrough خلّى إنتاج CPU كامل على silicon chip واحدة أصغر من dime ممكن. الـ microprocessors دي (computers-on-a-chip) بتتصنّع بكميات كبيرة وبتكلفة قليلة جدًا، وخلّت أنظمة الكمبيوتر رخيصة وصغيرة كفاية لتتحط على مكتب أو على الحِجر. الكمبيوترات الصغيرة دي اتسمّت microcomputers أو personal computers (PCs).
📍 p.30
أنواع الـ PCs🔥 مهم
أغلب الـ microcomputers للبيت أو الشغل هي desktop computers، وفي PCs أصغر قابلة للحمل (portable). مصطلحات الـ PCs بتتوزّع كالتالي:
  • Portable PCsبتشمل notebook و tablet و handheld و pocket computers.
  • Network computers (thin clients)PCs متصمّمة للاستخدام على الـ network بس.
  • Internet appliancesPCs أو devices متصمّمة للوصول للـ Internet بس.
  • PC compatiblesبتتسمى كمان Windows platform أو IBM-compatible PCs.
  • Macintoshالـ platform التانية اللي بيختار بينها أغلب مستخدمي الـ PCs.
📍 p.31 · p.32
PC compatible و Macintosh
الـ PC compatible هو personal computer مبني على Intel microcomputer أو CPUs متوافقة معاه. والـ Macintosh نوع personal computer بتصنّعه Apple.
📍 p.33 · p.34
Midrange Computers
الـ midrange computers (أو minicomputers) كمبيوترات متوسطة الحجم، وأغلبها بين الـ microcomputers والـ mainframes في الـ processing power. هي بتناسب شغل أكبر من اللي الـ microcomputer system بتقدر تتحمّله.
📍 p.35
Mainframes
الـ mainframes هي العمود الفقري لأغلب المنظمات الكبيرة، ومتخصصة في high-volume processing للـ business transactions. بتشتغل غالبًا 24 ساعة في اليوم: بتخدم عشرات الـ users على terminals وقت الشغل العادي، وبتعالج jobs كبيرة آخر الليل.
📍 p.36
Supercomputers
بعض المنظمات زي مراكز الأبحاث العلمية عندها احتياج استثنائي لـ processing power، فبتحتاج very fast speeds و extreme degrees of accuracy. بتوفّرها الـ supercomputers، وكتير منها بيتعمل بربط multiple PCs أو microprocessor chips مع بعض.
📍 p.37

Common System Components
الـ OS ليه تمانية components أساسية: Process Management, Main Memory Management, Secondary-Storage Management, I/O System Management, File Management, Protection System, Networking، و Command-Interpreter System.
📍 p.3
Process Management🔥 مهم
الـ process هو program في execution، وبيحتاج resources زي CPU time و memory و files و I/O devices عشان يخلّص شغله. الـ OS مسؤول عن الأنشطة دي:
  • Process creation and deletionإنشاء الـ processes وحذفها.
  • Process suspension and resumptionإيقاف الـ process مؤقتًا وإكمالها بعد كده.
  • Process synchronizationتوفير mechanisms تنظّم شغل الـ processes مع بعض.
  • Process communicationتوفير mechanisms تخلّي الـ processes تتواصل مع بعض.
📍 p.4
Main-Memory Management🔥 مهم
الـ memory هي large array من words أو bytes، وكل واحدة ليها address، وهي repository للـ data السريعة اللي بيشاركها الـ CPU والـ I/O devices. وهي volatile يعني بتفقد محتوياتها لو حصل system failure. الـ OS مسؤول عن:
  • Keep trackتتبّع أجزاء الـ memory المستخدمة حاليًا ومين بيستخدمها.
  • Decide which processes to loadتحديد الـ processes اللي تتعمل لها load لما مساحة تفضى.
  • Allocate and de-allocateتخصيص مساحة الـ memory وتحريرها عند الحاجة.
📍 p.5
Secondary-Storage Management
الـ main memory (primary memory) volatile وصغيرة جدًا عن إنها تستوعب كل الـ data والبرامج بشكل دائم، فلازم الكمبيوتر يوفّر secondary storage تعمل back up للـ main memory. أغلب الأنظمة الحديثة بتستخدم disks كـ principle on-line storage medium. أنشطة الـ OS هي Free space management و Storage allocation و Disk scheduling.
📍 p.6
I/O System Management
الـ I/O system بتتكوّن من buffer-caching system، و general device-driver interface، و drivers لـ hardware devices معيّنة.
📍 p.7
I/O System Operation🔥 مهم
الـ I/O devices والـ CPU بيشتغلوا concurrently. كل device controller مسؤول عن نوع device معيّن وليه local buffer، والـ CPU بينقل الـ data بين الـ main memory والـ local buffers، والـ I/O بيبقى من الـ device للـ local buffer. لما الـ controller يخلّص عمليته بيبلّغ الـ CPU عن طريق interrupt.
📍 p.8
Common Functions of Interrupts🔥 مهم
الـ interrupt بينقل الـ control للـ interrupt service routine (ISR) عن طريق الـ interrupt vector اللي فيه addresses كل الـ service routines. الـ interrupt architecture لازم يحفظ address of the interrupted instruction و state الـ CPU، وبتتعطّل الـ incoming interrupts أثناء معالجة interrupt تانية عشان نمنع lost interrupt. الـ trap هو software-generated interrupt بسبب error أو user request. والـ OS نفسه interrupt driven.
📍 p.9
Classes of Interrupts
الـ classes أربعة: Program (زي arithmetic overflow و division by zero و execute illegal instruction و reference outside user's memory space)، و Timer، و I/O، و Hardware failure.
📍 p.10
Interrupt Handler
الـ Interrupt handler برنامج بيحدد nature of the interrupt وبينفّذ الإجراءات المطلوبة. الـ control بيتنقل له، وهو غالبًا جزء من الـ OS.
📍 p.11
Interrupt Cycle
الـ processor بيعمل Fetch Cycle ثم Execute Cycle ثم Interrupt Cycle. في الـ Interrupt Cycle بيـ check على الـ interrupts: لو مفيش interrupts بيعمل fetch للـ next instruction بتاعة البرنامج الحالي، ولو في interrupt pending بيوقّف تنفيذ البرنامج الحالي وينفّذ الـ interrupt handler. لو الـ interrupts متعطّلة بيرجع للـ fetch على طول.
Fetch Next Instruction→Execute Instruction→Check for Interrupt→Process Interrupt
📍 p.12 · p.13
Multiple Interrupts
أول أسلوب هو الـ Disable interrupts أثناء معالجة interrupt: الـ processor بيتجاهل أي interrupt request جديدة. وفي الـ Sequential Order الـ interrupts بتتعطّل عشان الـ processor يكمّل شغله، وبتفضل pending لحد ما يفعّل الـ interrupts تاني، وبعد ما الـ handler routine تخلّص الـ processor بيـ check على additional interrupts.
📍 p.14 · p.15
Interrupt Priorities
الـ Higher priority interrupts بتخلّي الـ lower-priority interrupts تستنى، وبتتسبب في إن الـ lower-priority interrupt handler نفسه يتقاطع. ده بيحصل لما حاجة لازم تتمتص بسرعة زي input جاي من communication line.

  • CPU is running a programالبرنامج شغّال عادي.
  • An interrupt occursبيحصل interrupt (زي user يدوس على key).
  • OS saves CPU stateالـ OS بيحفظ حالة الـ CPU عشان يرجع لها بعد كده.

I/O Structure🔥 مهم
بداية الـ I/O بتتم بتحميل control information على الـ I/O device ونقل الـ control له. في نوعين من الـ I/O:
  • Synchronousبعد ما الـ I/O يبدأ الـ control مش بيرجع إلا بعد ما الـ I/O يخلّص.
  • Asynchronousبعد ما الـ I/O يبدأ الـ control بيرجع للـ program من غير ما يستنى الـ I/O يخلّص، والـ processes اللي مستنية I/O لازم تعمل check على status الـ device عشان تعرف إمتى خلّص.

Types of I/O
الرسم بيقارن النوعين: في الـ Synchronous الـ requesting process بتستنى (waiting) لحد ما الـ data transfer يخلّص، وفي الـ Asynchronous بتكمّل شغل وتستقبل النتيجة بعدين. الطبقات هي user (requesting process) ثم kernel (device driver, interrupt handler, hardware).

Direct Memory Access (DMA)
الـ DMA بيتستخدم مع الـ high-speed I/O devices اللي بتنقل information بسرعة قريبة من سرعة الـ memory. الـ device controller بينقل blocks of data من الـ buffer storage للـ main memory مباشرة من غير CPU intervention، والـ H/W المسؤول عن ده اسمه DMA channel.

File Management
الـ file هو collection of related information بيعرّفه اللي عمله، وغالبًا بيمثّل programs (source و object forms) أو data. الـ OS مسؤول عن:
  • File creation and deletionإنشاء الـ files وحذفها.
  • Directory creation and deletionإنشاء الـ directories وحذفها.
  • Primitivesدعم primitives للتعامل مع الـ files والـ directories.

Protection System
الـ Protection هو mechanism للتحكم في وصول الـ programs والـ processes والـ users للـ system و user resources. لازم الـ mechanism ده يعمل distinguish بين authorized و unauthorized usage، ويحدد الـ controls اللي هتتفرض، ويوفّر means of enforcement.
📍 p.22
Command-Interpreter System
أوامر كتير بتتبعت للـ OS عن طريق control statements بتتعامل مع process creation and management، و I/O handling، و secondary-storage management، و main-memory management، و file-system access، و protection، و networking. البرنامج اللي بيقرأ ويفسّر الـ control statements اسمه control-card interpreter أو command-line interpreter أو shell (في UNIX)، ووظيفته يجيب وينفّذ الـ next command statement.

System Calls🔥 مهم
الـ System calls هي الـ interface بين running program والـ operating system، وغالبًا بتتوفّر كـ assembly-language instructions. في لغات اتعرّفت تحل مكان الـ assembly في systems programming (زي C و Bliss و PL/360) بتسمح بالـ system calls تتعمل directly. وفي تلات طرق عامة لتمرير الـ parameters بين الـ program والـ OS:
  • Registersالـ parameters بتتمرّر في registers.
  • Table in memoryالـ parameters بتتخزّن في table في الـ memory.
  • Stackالـ program بتعمل Push للـ parameters على الـ stack، والـ OS بيعمل Pop لها.
📍 p.25
System Programs🔥 مهم
الـ System programs بتوفّر convenient environment لتطوير وتنفيذ البرامج، وأغلب الـ users بيشوفوا الـ OS من خلالها مش من خلال الـ system calls الفعلية. بتتقسّم لـ File manipulation, Status information, File modification, Programming language support, Program loading and execution, Communications، و Application programs.
📍 p.26
MS-DOS
الـ MS-DOS اتكتب عشان يوفّر most functionality في least space. مش متقسّم لـ modules، ومع إن عنده شوية structure فالـ interfaces والـ levels of functionality مش مفصولة كويس. وبينفّذ process واحدة في الوقت: الـ command interpreter والـ kernel في الأسفل، والـ process بتاخد جزء من الـ free memory.
📍 p.27 · p.28
UNIX Structure
الـ UNIX الأصلي كان محدود الـ structuring بسبب حدود الـ hardware، وبيتكوّن من part للـ systems programs و part للـ kernel. الـ kernel هو كل حاجة تحت الـ system-call interface وفوق الـ physical hardware، وبيوفّر file system و CPU scheduling و memory management وغيرهم، يعني عدد كبير من الـ functions في level واحد. ولما UNIX بيشغّل multiple programs بيبقى في الـ memory الـ kernel وبعده processes و interpreter و free memory.
📍 p.29 · p.30 · p.31
Layered Approach
الـ OS بيتقسّم لـ layers (levels)، كل layer مبنية فوق اللي تحتها: الـ layer 0 هي الـ hardware، والـ layer N هي الـ user interface، وكل layer بتستخدم functions و services الـ lower-level layers بس (modularity). التصميم الطبقي اتستخدم أول مرة في OS من ست layers: layer 5 هي user programs، و layer 4 هي buffering for input and output، و layer 3 هي operator-console device driver، و layer 2 هي memory management، و layer 1 هي CPU scheduling، و layer 0 هي hardware.
layer 5: user programs→layer 4: buffering for I/O→layer 3: operator-console device driver→layer 2: memory management→layer 1: CPU scheduling→layer 0: hardware

Virtual Machines
الـ virtual machine بتاخد الـ layered approach لنهايتها المنطقية: بتتعامل مع الـ hardware والـ OS kernel كأنهم كلهم hardware، وبتوفّر interface identical للـ bare hardware. الـ OS بيعمل illusion إن كل process شغّالة على processor خاص بيها وبـ virtual memory خاصة. موارد الـ physical computer بتتقسم عشان تتعمل الـ virtual machines: الـ CPU scheduling بيعمل ظهور إن كل user أو process عنده processor خاص، والـ Spooling والـ file system بيوفّروا virtual line printers و virtual card readers. وفي الـ model بتاع الـ virtual machine بيبقى في layer اسمها virtual machine بين الـ hardware والـ kernels.

Advantages and Disadvantages of Virtual Machines🔥 مهم
الـ virtual machine بتوفّر complete protection لموارد النظام لأن كل virtual machine معزولة عن الباقي، لكن العزل ده بيمنع direct sharing للـ resources. وهي perfect vehicle لـ operating systems research and development لأن التطوير بيتعمل على الـ virtual machine بدل الـ physical machine فمش بيعطّل شغل النظام العادي. أما عيبها فإنها difficult to implement بسبب الجهد المطلوب لتوفير exact duplicate للـ underlying machine.

Disadvantages

  • User goalsالـ OS لازم يكون convenient to use, easy to learn, reliable, safe، و fast.
  • System goalsالـ OS لازم يكون easy to design, implement, and maintain، وكمان flexible, reliable, error-free، و efficient.
📍 p.38
System Implementation
الـ OS تقليديًا بيتكتب بـ assembly language، ودلوقتي ممكن يتكتب بـ higher-level languages. الكود بـ high-level language بيتكتب أسرع، وأكثر compact، وأسهل في الفهم والـ debug. والـ OS بيبقى أسهل بكتير في الـ port (نقله لـ hardware تاني) لو اتكتب بـ high-level language.

الـ Mechanisms بتحدد إزاي تعمل الحاجة، والـ policies بتقرر إيه اللي هيتعمل. فصل الـ policy عن الـ mechanism مبدأ مهم جدًا لأنه بيدّي maximum flexibility لو قرارات الـ policy اتغيّرت بعدين.

Process Concept
الـ process هو program في execution، وبيتسمى كمان the entity اللي بيتخصص له processors، و dispatchable unit، و locus of control لـ procedure في execution. والـ textbooks بتستخدم كلمتين job و process تقريبًا بنفس المعنى.
📍 p.3
Process State🔥 مهم
الـ process بتغيّر حالتها وهي بتتنفّذ، وليها خمس حالات:
  • Newالـ process بتتعمل (being created).
  • Runningالـ instructions بتتنفّذ والـ process معاها الـ CPU.
  • Waiting (blocked)الـ process مستنية event يحصل زي I/O completion.
  • Readyالـ process مستنية تتخصص لها processor وممكن تستخدم الـ CPU.
  • Terminatedالـ process خلّصت تنفيذها.
📍 p.4

في process واحدة بس بتـ run في الوقت، وممكن كذا process تبقى ready أو waiting. الـ ready jobs في priority order، والـ waiting jobs unordered إلا لو مستنيين نفس الـ event. والانتقالات: New لـ Ready بـ admitted, Ready لـ Running بـ scheduler dispatch, Running لـ Ready بـ interrupt, Running لـ Waiting بـ I/O or event wait, Waiting لـ Ready بـ I/O or event completion، و Running لـ Terminated بـ exit.

Process Control Block (PCB)
الـ PCB اسمه كمان process descriptor، وهو data structure فيه معلومات عن الـ process:
  • Current stateحالة الـ process الحالية.
  • Unique identificationرقم أو هوية فريدة للـ process.
  • Pointer to parentمؤشر للـ process اللي أنشأتها.
  • Pointer to childمؤشر للـ process اللي أنشأتها هي.
  • Pointers to allocated resourcesمؤشرات للموارد المخصصة لها زي Memory range.

📍 p.6
Process Scheduling Queues
الـ Job queue هي set لكل الـ processes في النظام. الـ Ready queue هي set لكل الـ processes اللي في الـ main memory وجاهزة وبتستنى تتنفّذ. الـ Device queues هي sets من الـ processes اللي مستنية I/O device. والـ process migration هي انتقال الـ processes بين الـ queues المختلفة.
📍 p.7
Representation of Process Scheduling
الرسم بيوضّح إن الـ process بتخرج من الـ CPU لواحد من أربع طرق: I/O request فتروح I/O queue وبعدين ترجع للـ ready queue، أو time slice expired فترجع للـ ready queue، أو fork a child فالـ child بينفّذ وترجع بعده، أو wait for an interrupt وبعد ما الـ interrupt يحصل ترجع للـ ready queue.
📍 p.8
Schedulers🔥 مهم
في تلات schedulers:
  • Long-term schedulerأو job scheduler، بيختار الـ processes اللي تتحط في الـ ready queue، وبيشتغل نادرًا (seconds, minutes) فممكن يبقى بطيء، وهو اللي بيتحكم في degree of multiprogramming.
  • Short-term schedulerأو CPU scheduler، بيختار الـ process اللي تتنفّذ بعد كده وبيدّيها الـ CPU، وبيشتغل كل ملّي ثانية فلازم يبقى سريع.
  • Medium Term Schedulingبيعمل swap out للـ partially executed processes من الـ memory وبعدين swap in لها للـ ready queue.
📍 p.9 · p.10
I/O-bound و CPU-bound🔥 مهم
الـ I/O-bound process بتقضي وقت في الـ I/O أكتر من الحسابات وعندها many short CPU bursts. أما الـ CPU-bound process فبتقضي وقت في الحسابات أكتر وعندها few very long CPU bursts.
📍 p.10
Operations on Process🔥 مهم
العمليات على الـ process هي Create, Destroy, Suspend, Resume, Change process's priority, Block, Wakeup, Dispatch (يعني تـ run على الـ CPU)، وتمكين الـ process من التواصل مع process تانية (interprocess communication).
📍 p.11
Process Creation
إنشاء الـ process بيشمل تسمية الـ process، وإدخالها في الـ system's known process table، و set للـ initial priority، و Create للـ PCB، و Allocate للـ initial resources. الـ process ممكن تعمل spawn لـ process جديدة: اللي عملت اسمها parent process واللي اتعملت اسمها child process، والنتيجة hierarchical structure كل child فيه ليه parent واحد بس، والـ parent ممكن يبقى عنده أكتر من child. في الـ resource sharing بيتحقق واحد من التلاتة: الـ parent والـ children يشاركوا كل الـ resources، أو الـ children تشارك subset من resources الـ parent، أو مفيش resources مشتركة. وفي الـ execution: الـ parent والـ children يشتغلوا concurrently، أو الـ parent يستنى لحد ما الـ children يخلّصوا.
📍 p.12 · p.13 · p.14
Process Termination
إنهاء الـ process بيشمل إزالتها من النظام، ورجوع الـ allocated resources للنظام، ومسح الـ PCB. في بعض الأنظمة الـ spawned process بتتدمّر automatically لما الـ parent يتدمّر، وفي أنظمة تانية بتكمّل شغلها بشكل مستقل.
📍 p.15
Threads🔥 مهم
الـ thread (أو lightweight process) هو basic unit of CPU utilization وليه PCB خاص بيه. بيشارك peer threads في code section و data section و operating-system resources، والمشترك ده كله اسمه task. والـ traditional أو heavyweight process تساوي task فيها thread واحد. في الـ multiple threaded task لو thread واحد blocked بيقدر thread تاني في نفس الـ task يـ run، وتعاون الـ threads في نفس الـ job بيدّي higher throughput وأداء أحسن، والـ applications اللي محتاجة تشارك common buffer بتستفيد من الـ threads. وفي أنواع للـ threads:
  • Kernel-level threadsthreads بيدعمها الـ kernel نفسه.
  • User-level threadsبتستخدم thread library، وعيبها لو الـ kernel مش بيدعم threads.
  • Hybrid approachبيطبّق user-level و kernel supported threads مع بعض.
📍 p.16 · p.17
Interprocess Communication (IPC)🔥 مهم
الـ IPC هو mechanism للـ processes عشان تتواصل وتـ synchronize أفعالها. الـ Message system معناه إن الـ processes بتتواصل من غير shared variables. الـ IPC facility بيوفّر عمليتين: send (message) و receive (message)، والـ message size ممكن يكون fixed أو variable. ولو P و Q عايزين يتواصلوا لازم يعملوا communication link بينهم ويتبادلوا messages بـ send و receive. والـ link ممكن تتنفّذ physical (زي shared memory أو hardware bus) أو logical.
📍 p.18
Logical IPC
الـ logical IPC بيتحدد بخمس اختيارات: Direct or indirect communication، و Symmetric or asymmetric communication، و Automatic or explicit buffering، و Send by copy or send by reference، و Fixed size or variable size message.
📍 p.19
Direct Communication🔥 مهم
في الـ Direct communication الـ processes لازم تسمّي بعض صراحةً: send (P, message) بتبعت message للـ process P، وreceive (Q, message) بتستقبل message من الـ process Q. خصائص الـ link: بتتعمل automatically، وكل link مرتبطة بـ pair واحد من الـ processes بالظبط، وبين كل pair link واحدة، وممكن تبقى unidirectional لكن غالبًا bi-directional.
📍 p.20
Indirect Communication🔥 مهم
في الـ Indirect communication الـ messages بتتبعت وبتتستقبل من mailboxes (بتتسمى كمان ports)، وكل mailbox ليها unique ID، والـ processes بتتواصل بس لو بتشارك mailbox. خصائص الـ link: بتتعمل بس لو الـ processes بتشارك common mailbox، وممكن ترتبط بـ many processes، وكل pair ممكن يشاركوا أكتر من link، وممكن تبقى unidirectional أو bi-directional. وعمليات الـ mailbox هي create لـ mailbox جديد، و send و receive عن طريقه، و destroy.
Direct
  • processes name each other
  • automatic link
  • exactly one link per pair
VS
Indirect
  • mailboxes (ports)
  • link needs a shared mailbox
  • many processes, several links per pair

Buffering

Basic Concepts🔥 مهم
الـ CPU Scheduling هو أساس الـ multi-programmed OS، وهدفه maximize CPU utilization. الـ process خلال حياتها بتمر بدورة من CPU usage و I/O usage: دورة التنفيذ بتبدأ بـ CPU burst، ودورة الـ I/O بتبدأ بـ I/O burst.
📍 p.3
CPU Burst Times
تكرار الـ CPU bursts اتقاس بشكل مكثّف، والـ frequency graph بيتوصف بإنه exponential أو hyper exponential. الـ CPU bursts عادةً بتتكوّن من several short bursts و few longer bursts، والرسم بيبيّن إن الـ process بتتبادل CPU burst و I/O burst باستمرار.
📍 p.4 · p.5
Preemptive و Nonpreemptive Scheduling🔥 مهم
الـ scheduling discipline بتبقى nonpreemptive لو لما process تاخد الـ CPU مفيش حد يقدر ياخده منها، وبتبقى preemptive لو الـ CPU ممكن يتاخد. الـ preemptive مفيد في الأنظمة اللي الـ high-priority processes فيها محتاجة rapid attention، وعشان يبقى effective لازم processes كتير تفضل في primary memory عشان الـ next ready process تبقى جاهزة للـ CPU. أما في الـ nonpreemptive فالـ short jobs بتستنى الـ long jobs لكن المعاملة fair لكل الـ processes، والـ response time أكتر predictable لأن الـ incoming high-priority jobs مبتزحزحش الـ waiting jobs.
Preemptive
  • CPU can be taken away
  • rapid attention for high-priority
  • many processes kept in primary memory
VS
Nonpreemptive
  • CPU cannot be taken
  • short jobs wait for long jobs
  • fair, predictable response time
📍 p.6 · p.7
Scheduling Levels
في تلات مستويات للـ scheduling:
  • High-Level schedulingاسمه job scheduling أو admission scheduling، بيحدد أنهي job تدخل النظام، وبعد ما تتقبل بتتحوّل لـ processes أو groups of processes.
  • Intermediate-Level schedulingبيحدد الـ processes اللي تتنافس على الـ CPU، وبيستجيب للـ short term fluctuations بـ suspending و resuming للـ processes، وبيشتغل كـ buffer بين قبول الـ jobs في النظام وتخصيص الـ CPU ليها.
  • Low-Level schedulingبيحدد أنهي process هتاخد الـ CPU لما يفضى، وبينفّذه الـ dispatcher اللي بيشتغل many times per sec ولازم يفضل في primary storage طول الوقت. والـ Dispatch latency هو الوقت اللي الـ dispatcher بياخده عشان يوقّف process ويشغّل واحدة تانية.
📍 p.8 · p.9 · p.10 · p.11
Scheduling Criteria🔥 مهم
معايير الـ scheduling خمسة:
  • CPU utilizationإبقاء الـ CPU مشغول قدر الإمكان.
  • Throughputعدد الـ processes اللي بتخلّص تنفيذها في وحدة الزمن.
  • Turnaround timeالوقت الكلي لتنفيذ process معيّنة.
  • Waiting timeالوقت اللي الـ process قضّته في الـ ready queue.
  • Response timeالوقت من تقديم الـ request لحد ما أول response يتولّد وليس الـ output كله، وده في بيئة الـ time-sharing.
📍 p.12
Optimization Criteria
المطلوب الوصول لـ Max CPU utilization و Max throughput، و Min turnaround time و Min waiting time و Min response time.
📍 p.13
Priorities🔥 مهم
الـ Priorities ممكن تتحدد automatically بواسطة النظام أو externally، وممكن تكون earned أو bought، وممكن static أو dynamic. الـ Static priorities مبتتغيّرش وسهلة التنفيذ لكن مفيش response للتغيرات الخارجية. الـ Dynamic priorities ممكن تتغيّر حتى بعد وقت قصير، وتنفيذها أعقد لكنها responsive للتغيرات الخارجية.
📍 p.14
Scheduling Algorithms
الخوارزميات اللي بتتشرح هي Deadline Scheduling, FCFS, Round Robin (RR), Shortest-Job-First (SJF), Priority Scheduling, Multilevel Feedback Queue, Multiple-Processor Scheduling، و Real-Time Scheduling.
📍 p.15
Deadline Scheduling
في الـ Deadline Scheduling الـ jobs بتتجدول عشان تخلّص في وقت محدد (deadline): لو اتسلّمت في الميعاد بتاخد very high priority، ولو اتسلّمت بعد الـ deadline فهي worthless. وهو معقّد جدًا لأن الـ user لازم يحدد الـ resources المطلوبة بدقة مقدمًا وده نادر، والنظام لازم يشغّل الـ deadline job من غير ما يضر بالـ users التانيين، ولازم يخطّط الـ resources لحد الـ deadline، ووجود كتير من الـ deadline jobs نشطة مع بعض بيزوّد التعقيد، وبيحتاج intensive resources management.
📍 p.16 · p.17
First-Come, First-Served (FCFS)🔥 مهم
الـ FCFS (أو FIFO) بيـ dispatch الـ processes على حسب arrival time. هو fair في الشكل لكن unfair لأنه بيخلّي الـ short jobs تستنى الـ long jobs، وهو nonpreemptive، ونادرًا بيتستخدم كـ master scheme لكن ممكن يتستخدم مع scheme تانية. وترتيب الوصول بيأثر على الـ average waiting time: لو الـ long job وصلت الأول بيطلع الـ average كبير، ولو وصلت آخر بيطلع أقل بكتير، والـ FCFS مش بيضمن good response time.
🧮
الـ Waiting time للـ process في الـ FCFS يساوي مجموع الـ bursts اللي قبلها (لو الكل وصل في نفس الوقت)، والـ Turnaround time يساوي وقت انتهائها.
📍 p.18 · p.19 · p.20
Round Robin (RR) Scheduling🔥 مهم
في الـ Round Robin كل process بتاخد وحدة صغيرة من الـ CPU time اسمها time-slice أو quantum، وغالبًا 10-100 milliseconds. لو الوقت خلّص قبل ما الـ process تخلّص بتتعمل preempt وتتحط في آخر الـ ready queue ويتدّي الـ CPU للـ next ready process. لو في n processes في الـ ready queue والـ quantum هو q فكل process بتاخد 1/n من الـ CPU time على chunks مش أكتر من q في المرة، ومفيش process بتستنى أكتر من (n-1)q time units. وفي الـ performance: لو الـ q كبيرة جدًا بيتحوّل لـ FIFO، ولو q صغيرة لازم تبقى large بالنسبة لـ context switch وإلا الـ overhead يبقى عالي. الـ RR فعّال في الـ time sharing environments وبيضمن reasonable response time وبيخلّي الـ preemption overhead قليل. وكل ما الـ time quantum يصغر الـ context switches بتزيد فالـ overhead بيزيد.
📍 p.21 · p.22 · p.23 · p.24
Shortest-Job-First (SJF) Scheduling🔥 مهم
الـ SJF بيشغّل الـ waiting process اللي عندها أصغر estimated run-time to completion، وفيه scheme اتنين:
  • Nonpreemptiveلما الـ CPU يتدّي للـ process مبتتعملش preempt لحد ما تخلّص الـ CPU burst بتاعها.
  • Preemptive (SRTF)لو process جديدة وصلت وعندها CPU burst أقل من الـ remaining time للـ process اللي شغّالة بتتعمل preempt، والـ scheme دي اسمها Shortest-Remaining-Time-First.
🏆
الـ SJF optimal لأنه بيدّي minimum average waiting time لمجموعة processes معيّنة، وعنده lower average turnaround من الـ RR لكن response أطول.
📍 p.25 · p.26 · p.27
Priority Scheduling🔥 مهم
كل process بيتربط بيها priority number (integer)، والـ CPU بيتخصّص للـ process اللي أعلى priority (الـ smallest integer يساوي highest priority)، والـ scheduling ممكن يكون preemptive أو nonpreemptive. الـ SJF هو priority scheduling والـ priority فيه هو predicted next CPU burst time. المشكلة هي Starvation لأن الـ low priority processes ممكن ما تتنفّذش أبدًا، والحل هو Aging يعني مع الوقت بنزوّد الـ priority بتاع الـ process.
📍 p.28
Multilevel Queue
الـ ready queue بتتقسّم لـ separate queues: foreground (interactive) و background (batch)، وكل queue ليها scheduling algorithm خاص بيها: الـ foreground بـ RR والـ background بـ FCFS. ولازم يتعمل scheduling بين الـ queues: إما Fixed priority scheduling (نخدم كل الـ foreground وبعدها الـ background وفيه احتمال starvation)، أو Time slice (كل queue بتاخد نسبة معيّنة من الـ CPU time وتوزّعها على الـ processes بتاعتها). والرسم بيرتّب الـ queues من الأعلى priority للأقل: system processes, interactive processes, interactive editing processes, batch processes, student processes.
📍 p.29 · p.30
Multilevel Feedback Queue🔥 مهم
في الـ Multilevel Feedback Queue الـ process ممكن تتنقل بين الـ queues المختلفة، وبكده ممكن نطبّق الـ aging. الـ scheduler بيتعرّف بالـ parameters دي:
  • Number of queuesعدد الـ queues.
  • Algorithm for each queueالـ scheduling algorithm لكل queue.
  • Upgrade methodالطريقة اللي بتحدد إمتى نرفع process لـ queue أعلى.
  • Demote methodالطريقة اللي بتحدد إمتى ننزّل process لـ queue أقل.
  • Queue entry methodالطريقة اللي بتحدد الـ queue اللي تدخلها الـ process لما تحتاج service.
🔽
في المثال بتاع التلات queues: الـ job الجديدة بتدخل الـ queue الأولى بـ quantum صغير، ولو ماخلصتش بتتنقل للـ queue اللي بعدها بـ quantum أكبر، ولو لسه ماخلصتش بتتنقل للـ queue الأخيرة اللي بتشتغل FCFS.
📍 p.31 · p.32
Multiple-Processor Scheduling
الـ CPU scheduling بيبقى أعقد لما فيه CPUs كتير:
  • Homogeneous systemالـ processes متطابقة في الـ functionality.
  • Heterogeneous systemالبرامج لازم تتعمل compile لـ instructions الـ processors المناسبة.
  • Load Sharing (Load Balancing)بيستخدم queue لكل processor.
  • Self-Scheduling (Symmetric Multiprocessing)بيستخدم common ready queue لكل الـ processors.
  • Master-Slave (Asymmetric Multiprocessing)هو الاسم التاني للـ Asymmetric Multiprocessing، وبيخفّف الحاجة لـ data sharing.
📍 p.33 · p.34
Real-Time Scheduling🔥 مهم
الـ Hard real-time systems لازم تعرف exact time لكل task، والـ scheduling إما pre-determined أو بـ resource reservation: الـ task بتحاول تحجز الـ resources قبل ما تبدأ، وبتتـ reject لو الـ resources كلها مش متاحة. أما الـ Soft real-time systems فالـ real-time processes بتاخد priority على باقي الـ processes، ولازم الـ dispatch latency تبقى صغيرة وبتتحقق عادةً بالـ preemption.

First-Come, First-Served (FCFS)🔥 مهم
الـ FCFS (أو FIFO) بيـ dispatch الـ processes على حسب arrival time. هو fair في الشكل لكن unfair لأنه بيخلّي الـ short jobs تستنى الـ long jobs، وهو nonpreemptive، ونادرًا بيتستخدم كـ master scheme لكن ممكن يتستخدم مع scheme تانية. وترتيب الوصول بيأثر على الـ average waiting time: لو الـ long job وصلت الأول بيطلع الـ average كبير، ولو وصلت آخر بيطلع أقل بكتير، والـ FCFS مش بيضمن good response time.

Round Robin (RR) Scheduling🔥 مهم
في الـ Round Robin كل process بتاخد وحدة صغيرة من الـ CPU time اسمها time-slice أو quantum، وغالبًا 10-100 milliseconds. لو الوقت خلّص قبل ما الـ process تخلّص بتتعمل preempt وتتحط في آخر الـ ready queue ويتدّي الـ CPU للـ next ready process. لو في n processes في الـ ready queue والـ quantum هو q فكل process بتاخد 1/n من الـ CPU time على chunks مش أكتر من q في المرة، ومفيش process بتستنى أكتر من (n-1)q time units. وفي الـ performance: لو الـ q كبيرة جدًا بيتحوّل لـ FIFO، ولو q صغيرة لازم تبقى large بالنسبة لـ context switch وإلا الـ overhead يبقى عالي. الـ RR فعّال في الـ time sharing environments وبيضمن reasonable response time وبيخلّي الـ preemption overhead قليل. وكل ما الـ time quantum يصغر الـ context switches بتزيد فالـ overhead بيزيد.
📍 L4: p.21, p.22, p.23, p.24
Shortest-Job-First (SJF) Scheduling🔥 مهم
الـ SJF بيشغّل الـ waiting process اللي عندها أصغر estimated run-time to completion، وفيه scheme اتنين:
  • Nonpreemptiveلما الـ CPU يتدّي للـ process مبتتعملش preempt لحد ما تخلّص الـ CPU burst بتاعها.
  • Preemptive (SRTF)لو process جديدة وصلت وعندها CPU burst أقل من الـ remaining time للـ process اللي شغّالة بتتعمل preempt، والـ scheme دي اسمها Shortest-Remaining-Time-First.
🏆
الـ SJF optimal لأنه بيدّي minimum average waiting time لمجموعة processes معيّنة، وعنده lower average turnaround من الـ RR لكن response أطول.

Multilevel Feedback Queue🔥 مهم
في الـ Multilevel Feedback Queue الـ process ممكن تتنقل بين الـ queues المختلفة، وبكده ممكن نطبّق الـ aging. الـ scheduler بيتعرّف بالـ parameters دي:
  • Number of queuesعدد الـ queues.
  • Algorithm for each queueالـ scheduling algorithm لكل queue.
  • Upgrade methodالطريقة اللي بتحدد إمتى نرفع process لـ queue أعلى.
  • Demote methodالطريقة اللي بتحدد إمتى ننزّل process لـ queue أقل.
  • Queue entry methodالطريقة اللي بتحدد الـ queue اللي تدخلها الـ process لما تحتاج service.
🔽
في المثال بتاع التلات queues: الـ job الجديدة بتدخل الـ queue الأولى بـ quantum صغير، ولو ماخلصتش بتتنقل للـ queue اللي بعدها بـ quantum أكبر، ولو لسه ماخلصتش بتتنقل للـ queue الأخيرة اللي بتشتغل FCFS.
📍 L4: p.31, p.32
Real-Time Scheduling🔥 مهم
الـ Hard real-time systems لازم تعرف exact time لكل task، والـ scheduling إما pre-determined أو بـ resource reservation: الـ task بتحاول تحجز الـ resources قبل ما تبدأ، وبتتـ reject لو الـ resources كلها مش متاحة. أما الـ Soft real-time systems فالـ real-time processes بتاخد priority على باقي الـ processes، ولازم الـ dispatch latency تبقى صغيرة وبتتحقق عادةً بالـ preemption.
